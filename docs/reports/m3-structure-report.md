# M3 Rules-only 结构识别报告

日期：2026-09-20；应用版本：0.7.0；Profile：`scau_undergraduate_2026_v1`。

## 一句话说明

系统现在能在任意输入的 DOCX 文档块上提出可追溯的结构角色，建立标题父级，标出歧义，接受绑定原文哈希的人工纠正，并把可靠定位的对象送入 M2 规则比较；本阶段没有修改 DOCX。

## 实现结果

- 识别封面文档类型、标题和字段，原创性/授权声明，中英文摘要及关键词，目录，四级标题，正文，缩略词表，表格及单元格，图片、公式、图表题，参考文献、附录和致谢。
- 综合 Word 段落样式、有效大纲级别、编号文本、目录域、对象类型、章节标志和文档顺序。标题样式与编号冲突、普通编号列表和仅凭编号猜测的图表题进入人工复核。
- 跨段落复杂 TOC 域、嵌套 PAGEREF 域和简单 TOC 域不会被误当作正文标题。字段未闭合、包装块和嵌套表格产生结构警告。
- 每个 M1 已表示的文档块恰好有一条判定，包含原始定位、角色、规则范围、分区、父级、依据、判断来源、文本哈希和字符数。默认不包含原文预览。
- 人工纠正绑定输入 SHA-256，并校验 block ID、重复项、对象类型、语义角色和规则范围。纠正后重算后续分区和标题父级，记录审查人、范围和理由。
- 已定位对象进入 M2 比较器。标签/值片段尚未定位时返回未评估；暂定规则继续返回证据不足；公式等不支持的实际格式不产生通过结论。

## 真实样本结果

| 样本 | 已表示文档块 | 优先复核入口 | 含继承状态的待确认项 | 已确认规则比较 |
|---|---:|---:|---:|---|
| 论文原稿 | 785 | 28 | 179 | 2 pass / 2 fail |
| 官方模板 | 392 | 9 | 9 | 3 pass / 1 fail |

论文原稿识别出 5 个一级标题、16 个二级标题、31 个三级标题、1 个四级标题、216 个正文块、55 个公式段落、14 个图片候选、13 个图题、6 个表题、22 条参考文献和 11 个表格。待确认入口主要是纯图片段落、仅靠文本模式识别的表题、可能是普通列表的编号段落，以及位于特殊区域的表格。

论文原稿共有 4379 次暂定规则比较返回 `evidence_insufficient`，另有 48 条规则尚未应用。这里的数字是“对象 × 原子规则”的检查次数，不能当作准确率、独立规则覆盖率或学校合规结论。真实文件及报告保留在 `.paperalign`，未进入 Git；输入 SHA 和内容指纹在识别前后不变。

## 测试覆盖

M3 的合成回归覆盖：

- 中英文摘要边界、同角色的标题/正文规则范围和首段/后续段选择；
- 目录域跨段落、嵌套字段、简单字段、未闭合字段和目录样式；
- 四级标题、标题父级、层级跳跃、样式/编号冲突、普通编号列表；
- 图表题文本与 Caption 样式组合、公式对象、纯图片段落；
- 缩略词三线表的 0.5 pt / 1 pt 差异和表格单元格父级；
- 人工纠正的错误哈希、未知/重复块、对象类型和角色/范围不匹配；
- 无预览报告不包含正文，有预览时 HTML 转义且最多 20 字；输出必须留在 `.paperalign`。

完整工程回归通过：113 项后端测试、52 个源文件的严格类型检查、Ruff、Schema 同步、Python 依赖检查、前端类型检查、1 项前端测试和生产构建均成功；npm 审计报告 0 个漏洞。两条来自 Starlette/httpx 与 AnyIO 的第三方弃用提示未导致失败。M3 的启发式分数用于排序复核，不是经标注数据计算的准确率。要量化 precision/recall，需要先对模板和论文建立人工金标。

## 如何人工验收

运行 README 中的 `paperalign classify` 命令，打开 `structure_review.html`，按“待确认定位”逐项检查。优先核对 28 个入口；表格确认后，其单元格的继承状态由系统重算，无须逐格重复判断。

将需要纠正的项目写入 `corrections.json`。对于 `cover`、`abstract_zh`、`abstract_en` 和 `table_of_contents` 这类同一语义角色对应多个格式范围的情况，同时填写 `scope`，例如 `abstract_en_title` 或 `abstract_en_body`。重新运行后检查纠正来源是否为 `user`、后续区域与标题父级是否正确，并保留纠正理由作为评测金标的起点。

## 剩余四个主要阶段

1. M4：只把待确认结构交给 AI 提议，校验输出并与 Rules-only 对照；记录 token、耗时、失败降级和评测结果。
2. M5：完成本地上传、结构审查、格式问题、规则确认和任务状态界面。
3. M6：生成新 DOCX 副本，按确认规则执行确定性修改，输出改动清单并校验内容指纹。
4. M7：在 Word 中完成字段、目录与页码更新，做幂等、文件可打开、分页视觉与真实论文回归。

为了加快开发，后续继续复用同一份 StructureReport、FormatRule 和 RuleValidationResult，不为 AI、界面和排版分别重建领域对象。完整性的门槛保持为：可追溯、可纠正、原文可恢复、失败有明确状态、真实样本通过 Word 验收。
