# PaperAlign M1 实施报告

> 版本：0.2.0
> 日期：2026-09-19
> 分支：feat/m1-docx-readonly-analysis
> 结论：M1 代码与合成文档验收完成；真实脱敏论文验证尚待用户提供样本。

## 1. 一句话结论

PaperAlign 已具备一个不依赖大模型、不修改原文件、输出确定且可审计的 DOCX 只读分析底座，能够生成文档画像、内容指纹、不支持对象报告和 Markdown 摘要。

## 2. 本阶段完成内容

### 2.1 DOCX 安全读取

- 验证 .docx 扩展名与 ZIP 文件签名；
- 校验 ZIP CRC 和三个必要部件；
- 拒绝绝对路径、反斜杠路径和 .. 路径穿越；
- 拒绝加密部件；
- 限制部件数量、单部件大小、总解压大小和压缩比；
- XML 禁止实体解析和网络访问；
- 分析前后比对输入文件 SHA-256。

### 2.2 文档画像

当前可提取：

- 主文档顶层段落及直接样式信息；
- 表格、行数、单元格和单元格文本；
- 样式 ID、名称、类型及继承来源；
- 页面大小、页边距、分节类型和页码设置；
- 页眉、页脚、脚注、尾注和批注文本部件；
- 简单字段及复杂字段指令；
- 图片资源的类型、大小和 SHA-256；
- 段落中的分页符、分栏符、绘图和超链接标记。

### 2.3 内容指纹

采用 SHA-256，为两个不同问题保留两类哈希：

1. 文件哈希：证明输入 DOCX 文件字节是否发生变化；
2. 内容指纹：忽略字体、字号等格式差异，保护正文段落、表格单元格、页眉页脚、脚注、字段指令和媒体字节。

文本只进行最小规范化：

- CRLF、CR 统一为 LF；
- Unicode 统一为 NFC；
- 空文本单元不参与聚合；
- 不折叠空格，不去除标点，不改写文字。

聚合指纹保留内容单元顺序和类型，因此文字移动、增删或媒体变化都会导致指纹改变；仅改变字体时指纹保持不变。

### 2.4 不支持对象检测

当前检测并分级：

- 阻断自动格式化：宏、ActiveX、OLE、嵌入包、altChunk、越界关系、丢失关系目标；
- 需要人工复核：外部关系、图表、SmartArt、文本框、公式、修订、内容控件、嵌套表格、数字签名；
- 仅记录：自定义 XML。

报告不是简单的布尔值。每个对象包含类别、严重程度、所在部件、关系类型、目标和后续处置策略。

## 3. CLI 使用

~~~powershell
.\.venv\Scripts\python.exe -m paperalign analyze .\path\to\anonymized-thesis.docx --out .\.artifacts\sample
~~~

输出：

~~~text
document_profile.json
content_fingerprint.json
unsupported_objects.json
analysis_summary.md
~~~

写出采用临时文件加原子替换；输入文件以只读方式打开，输出写入独立目录。

## 6. 关键技术决策

### 为什么不用 python-docx 一把梭

python-docx 适合常见段落和样式操作，但不能完整暴露所有 OPC 部件、关系、字段、宏、ActiveX 和嵌入对象。M1 直接读取 ZIP + OOXML，并保留未来在格式化阶段使用 python-docx 的可能性。

### 为什么 M1 不接大模型

文件完整性、ZIP 安全、关系解析和哈希验证都是确定性问题。使用大模型不会提高正确性，反而会增加成本、隐私暴露和不可复现性。AI 应在后续阶段处理“这段文字是什么语义角色”一类模糊问题。

### 为什么先产出 JSON

JSON 是 CLI、API、前端、规则引擎和评测之间的稳定契约。先稳定契约，可以避免后续每一层重新解析 Word。

## 7. 已知限制

1. 当前验收样本是合成 DOCX，尚未使用用户的真实脱敏论文；
2. 目前记录直接段落样式和样式定义，但尚未计算完整的 Word 样式级联结果；
3. 顶层表格已经建模，嵌套表格只报告为人工复核；
4. 公式、文本框、SmartArt 和图表会被发现，但尚未转换成完整语义块；
5. M1 不渲染页面，因此不能判断分页视觉效果；
6. M1 不判断华农格式是否合规，也不自动修改文档；
7. ZIP 安全上限是工程防护，不等同于恶意文件沙箱；
8. 当前 FastAPI 测试存在 2 条上游弃用警告，不影响结果，后续依赖升级时处理。

## 8. M1 到 M2 的门槛

在开始写华农规则前，建议先用两份材料做真实验证：

1. 官方标准样稿转换得到的 .docx；
2. 用户提供的脱敏论文原稿 .docx。

需要将遇到的每个真实边缘对象缩减成合成回归 fixture。真实验证通过后，再进入 M2：建立带证据、状态、实现器和验证器的 SCAU P0 规则 Profile。
