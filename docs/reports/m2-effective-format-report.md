# PaperAlign M2.1 有效格式解析实施报告

> 版本：0.4.0
> 日期：2026-09-19
> 状态：M2.1 代码完成，尚未推送

> 后续更新：2026-09-20 的审计修复、Word 抽查及 M2.2 结果见 `m21-audit-m22-report.md`。以下为初版实现记录，测试数和限制以新报告为准。

## 1 一句话结论

PaperAlign 现在可以把 Word 中分散在文档默认值、样式继承、字符样式和直接格式里的设置合并成最终有效格式，并为每个属性保留来源；这让后续验证器能够解释“实际值是什么、从哪里继承、为什么最终生效”。

## 2 为什么需要这一阶段

Word 文件中看见的格式不一定写在当前段落或文字 run 上。属性值可能来自：

```text
文档默认值
  → 基础段落样式
  → 派生段落样式
  → 字符样式
  → 段落或文字的直接格式
```

如果只读取第一个文字 run，或者把 XML 中没有显式出现的属性当成“缺失”，就会把继承值误判为错误。M2.1 将“原始声明”和“最终有效值”分开，仍保留 M2.0 的直接格式簇用于审计。

## 3 已实现能力

- 解析 `styles.xml` 中的 `docDefaults`；
- 递归展开 `basedOn` 样式链，并检测缺失样式和继承环；
- 合并段落样式中的段落属性与文字属性；
- 在单个文字 run 上继续叠加字符样式和直接格式；
- 解析中文、西文和复杂文字字体、字号、粗体、斜体与颜色；
- 解析对齐、行距、段前段后、首行及左右缩进、大纲级别、与下段同页和段前分页；
- 按属性记录最终来源，不只记录整个段落的笼统来源；
- 将相同有效格式的可见文字 run 聚合，并只输出数量与索引，不保存正文；
- 将结果纳入 `template_evidence.json` 和 JSON Schema。

## 4 数据结构

每个正文层段落对应一个 `EffectiveParagraphFormat`：

- `paragraph_index`：稳定的正文段落索引；
- `paragraph_style_id/name`：最终选用的段落样式；
- `paragraph`：有效段落属性与逐属性来源；
- `runs`：按最终文字格式聚合的格式组、字符样式、数量和样本索引。

来源值示例：

- `doc_defaults`：来自 Word 文档默认值；
- `paragraph_style:Base`：来自基础段落样式；
- `paragraph_style:Derived`：来自派生段落样式；
- `character_style:Emphasis`：来自字符样式；
- `direct_paragraph`：来自段落直接格式；
- `direct_run`：来自文字 run 直接格式。

## 5 测试设计

合成 DOCX 构造了完整覆盖链：默认宋体/Times New Roman 与 10.5 pt，基础样式改为黑体、12 pt、加粗和左对齐，派生样式再改为 14 pt、居中；字符样式增加 Arial 和斜体，第二个 run 最后用直接格式把字号覆盖为 15 pt。

测试同时断言最终值和来源：例如 15 pt 必须来自 `direct_run`，Arial 必须来自 `character_style:Emphasis`，居中必须来自派生段落样式，而不能只断言“最后看起来对”。

- 既有提示仍保留：M2.0 的直接格式簇只读取每段第一个可见文字 run，不能替代 M2.1 的有效格式结果。

## 8 当前边界

- 当前只解析 `w:body` 的直接子段落，表格单元格、页眉页脚、脚注和文本框内段落尚未进入有效格式清单；
- 主题字体 `asciiTheme/eastAsiaTheme` 尚未解析到具体字体名；
- 编号样式、条件表格样式和复杂脚本的全部 OOXML 级联规则尚未覆盖；
- 粗体、斜体等 toggle 属性当前按覆盖模型处理，后续要用更多 Word 互操作样本验证复杂样式链；
- 本阶段只输出事实证据，不判断某段是标题、正文或图题，也不做合规结论或自动修改。
