# PaperAlign M1 面试讲解

> 使用原则：只讲已经完成和验证的内容。当前可以说“完成了只读分析底座”，不能说“已经实现自动排版”。

## 1. 30 秒版本

我正在独立开发一个论文格式诊断与安全排版工具 PaperAlign。第一阶段我没有直接让大模型修改 Word，而是先做了一个确定性的 DOCX 只读分析器。它会把 DOCX 当成 OOXML 压缩包，解析段落、表格、样式、分节、页眉页脚、字段和图片，生成文档画像；同时用 SHA-256 对正文、表格、字段和媒体建立内容指纹，并检测宏、嵌入对象、altChunk、外部关系等风险。当前 CLI 能稳定输出四份报告，14 项测试通过，覆盖率 90%，但我也明确把真实论文验证和自动排版留在后续阶段。

## 2. 90 秒版本

PaperAlign 要解决的问题不是简单地“把字体改成宋体”，而是如何在不破坏论文内容的前提下理解 Word 结构、发现格式问题并安全修改。

我把系统拆成三层。第一层是确定性文档底座，也就是现在完成的 M1：读取 DOCX 的 ZIP 和 OOXML，生成统一的文档画像。第二层是后续的语义识别，用规则判断标题、正文、摘要等角色，在模糊位置才调用 AI，并允许用户确认。第三层才是确定性排版和独立验证。

M1 里我重点解决两个风险。第一个是文件安全。我限制 ZIP 部件数量、大小和压缩比，禁止 XML 外部实体，识别宏、OLE、ActiveX、嵌入包和外部关系。第二个是内容保护。我同时计算文件哈希和格式无关的内容指纹。字体变化时内容指纹不变，正文或图片变化时一定改变，未来排版后可以用它证明没有误改内容。

目前这个阶段不依赖大模型，也没有声称能够自动排版。下一步是拿官方样稿和脱敏论文做真实回归，然后再建立华农格式规则库。

## 3. STAR 版本

### Situation

论文自动排版看起来像格式批处理，但真实 DOCX 里包含样式继承、分节、域、页眉页脚、图片、嵌入对象等复杂结构。直接让模型或脚本修改，最大的风险不是“排得不够漂亮”，而是内容丢失且无法证明。

### Task

我要先建立一个可信的文档输入层：不修改原文件，完整描述关键结构，识别暂不支持的对象，并为后续修改提供内容完整性基线。

### Action

- 使用 ZIP + lxml 直接读取 OPC/OOXML；
- 建立 Pydantic 文档画像和 JSON Schema；
- 设计包大小、路径、压缩比、XML 和关系安全检查；
- 将正文、表格、页眉页脚、脚注、字段和媒体纳入 SHA-256 指纹；
- 将宏、OLE、ActiveX、altChunk、外部关系等按阻断、人工复核、仅记录分级；
- 用运行时合成的 DOCX 覆盖正常与危险场景；
- 把 CLI 输出做成确定性 JSON，重复运行逐字节一致。

### Result

- CLI 输出文档画像、内容指纹、不支持对象和 Markdown 摘要；
- 14 项后端测试通过，覆盖率 90%；
- Ruff 和 mypy strict 通过；
- 验证了仅修改字体时内容指纹不变、修改文字时指纹变化；
- 验证了分析前后输入文件字节一致；
- 明确保留了真实脱敏论文验证这一下一阶段门槛。

## 4. 高频追问与回答

### Q1：为什么不先写一个 Prompt，让模型直接排版？

因为这个问题包含两类子问题。语义角色识别有模糊性，适合 AI；ZIP 完整性、字体设置、分节修改和内容校验是确定性问题，应该交给程序。让模型直接修改 DOCX 很难保证可重复、可追溯和内容零损失。我采用的是“规则兜底、AI 处理歧义、程序执行修改、验证器独立验收”。

### Q2：M1 里为什么完全没有 AI？

这是刻意的。M1 解决的是文件解析和安全边界，引入 AI 没有收益。先建立可信结构，后续模型只接收必要的文本块和结构特征，可以减少 Token、隐私暴露和幻觉影响。

### Q3：DOCX 不就是一个 Word 文件吗，为什么这么复杂？

.docx 实际上是一个 OPC ZIP 包，正文、样式、编号、页眉页脚、图片和关系分别放在不同部件里。一个段落看起来正常，不代表关系目标、字段或嵌入对象是安全的。因此只读取 document.xml 不足以支撑安全排版。

### Q4：为什么不用 python-docx？

我不是完全排斥它，而是按层使用。python-docx 适合后续常规格式写入；M1 需要看到宏、关系、altChunk、嵌入对象和原始字段，这些必须查看底层 OOXML。采用高层 API 加定向 OOXML 的组合更合适。

### Q5：你怎么证明没有修改论文内容？

有两层证明。第一层是输入文件分析前后的文件 SHA-256，保证分析阶段没有动原文件。第二层是格式无关的内容指纹，覆盖正文、表格、页眉页脚、脚注、字段指令和图片。未来格式化前后比较内容指纹，字体和段落格式改变不会影响它，但文字、顺序、字段或图片变化会被发现。

### Q6：为什么不直接比较整个 DOCX 的文件哈希？

格式化一定会改变 XML 和 ZIP 字节，所以整个文件哈希必然变化。内容指纹把“允许变化的格式”和“必须保持的内容”分离，才能用于格式化前后的完整性验收。

### Q7：检测到不支持对象以后怎么办？

不是统一报错。我定义了三种策略：阻断自动格式化、需要人工复核、仅记录。例如宏和嵌入包默认阻断；普通外部超链接需要人工复核；自定义 XML 先记录。这样产品可以解释为什么不能一键继续。

### Q8：如何保证结果可复现？

分析过程不含时间戳和随机数；内容块按文档顺序编号，关系和资源按稳定键排序；JSON 固定 UTF-8、字段顺序和缩进。测试中同一输入分析两次，四份产物逐字节一致。

### Q9：目前最大的局限是什么？

目前验证主要基于合成 DOCX，还没有用真实脱敏论文跑过完整回归；同时尚未计算完整样式级联，也不处理公式、文本框和 SmartArt 的深层语义。我不会把 M1 描述成可用的自动排版产品，真实样本验证是进入规则阶段前的门槛。

### Q10：下一步 AI 会放在哪里？

在确定性解析之后、格式化之前。规则先根据 Word 样式、编号、关键词和位置识别结构；只有低置信度块才把必要文本和邻近上下文发给模型；模型输出结构化候选和置信度，高影响歧义再交给用户确认。

## 5. 可放入简历的项目表述

> 以下数字基于当前 M1 自动化验证，真实论文效果数据应等真实样本评测后再补充。

- 独立设计 PaperAlign 论文格式诊断与安全排版系统，完成 DOCX 只读分析底座，基于 ZIP/OOXML 解析段落、表格、样式、分节、字段、页眉页脚及媒体资源，输出版本化 JSON 文档画像。
- 设计格式无关的 SHA-256 内容指纹，覆盖正文、表格、字段及媒体；验证字体变化不影响指纹、文字或媒体变化可被检测，并通过分析前后文件哈希确保原稿未被修改。
- 建立宏、ActiveX、OLE、嵌入包、altChunk、外部关系等风险对象的分级处置机制；实现确定性 CLI 四类产物，后端 14 项测试通过、覆盖率 90%，Ruff 与 mypy strict 检查通过。

## 6. 演示时的讲解顺序

1. 展示输入是一份合成或脱敏 DOCX；
2. 执行 python -m paperalign analyze；
3. 先打开 analysis_summary.md 讲产品结果；
4. 打开 document_profile.json 展示结构而不是全文；
5. 对比两份仅字体不同的文档，展示内容指纹一致；
6. 使用危险 fixture 展示宏、嵌入对象和外部关系被阻断；
7. 最后明确：M1 是安全地基，M2 才是学校规则，M3/M4 才是语义识别和 AI 对照。

## 7. 不应该在面试中声称

- 不要说“已经支持任意学校模板”；
- 不要说“已经完成自动排版”；
- 不要说“真实论文准确率达到多少”，因为尚未完成真实数据标注；
- 不要说“用了大模型”，M1 的价值恰恰是知道哪里不该用模型；
- 不要说“保证所有 DOCX 绝对安全”，当前是工程级检查，不是恶意文件沙箱；
- 不要把合成测试覆盖率等同于真实场景成功率。
