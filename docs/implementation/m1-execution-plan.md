# M1 执行计划：DOCX 只读分析

> 状态：已完成（合成文档验收）
> 分支：`feat/m1-docx-readonly-analysis`
> 输入：单个 `.docx`
> 输出：文档画像、内容指纹、不支持对象报告、Markdown 摘要

## 1. 目标

建立所有后续语义识别和格式化的可信输入层。M1 只读取 DOCX，不修改、不另存、不调用大模型，也不判断论文格式是否正确。

## 2. 流水线

```text
输入路径
  → 扩展名、文件签名和 ZIP 完整性检查
  → 包大小、路径、压缩比和必要部件检查
  → OOXML 主文档、关系、样式、分节、页眉页脚、字段和媒体解析
  → DocumentBlock 列表与统计信息
  → 受保护文本规范化与 SHA-256 指纹
  → 宏、ActiveX、OLE、嵌入文件、altChunk、外部关系等风险检测
  → 原文件前后哈希比对
  → 原子写出四类产物
```

## 3. 产物

```text
document_profile.json
content_fingerprint.json
unsupported_objects.json
analysis_summary.md
```

JSON 采用固定字段、稳定排序和 UTF-8 编码；相同输入重复分析应得到完全相同的结果。

## 4. 内容指纹边界

- 纳入：主文档段落、表格单元格、页眉和页脚可见文本；
- 保留内容顺序；
- 将换行统一为 `\n`，Unicode 统一为 NFC；
- 不纳入字体、字号、段落样式、分页和其他格式属性；
- 同时输出每个内容单元哈希与聚合哈希；
- 目标是证明“格式操作前后文字内容没有变化”，不是代替文件哈希。

## 5. 安全边界

- 拒绝非 ZIP、伪 `.docx`、损坏 ZIP 和缺少主文档的包；
- 拒绝绝对路径和 `..` 路径；
- 对文件数、单项解压大小、总解压大小和压缩比设上限；
- XML 禁止实体解析和网络访问；
- 宏、ActiveX、OLE、嵌入包、altChunk、外部关系明确报告；
- 分析前后重新计算输入文件 SHA-256，不一致则失败；
- 输出不得写回输入目录中的同名文件。

## 6. 测试计划

- 最小合法 DOCX；
- 段落、标题样式、表格、图片、字段、分节、页眉页脚；
- 样式变化不改变内容指纹；
- 文本变化必须改变内容指纹；
- 宏、嵌入对象、altChunk、外部关系检测；
- 路径穿越、伪 DOCX、损坏 XML、缺少必要部件；
- 重复运行字节级一致；
- CLI 生成四项产物且不修改输入。
