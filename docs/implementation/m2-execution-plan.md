# M2 执行计划 华南农业大学本科论文格式规则 Profile

> 状态：M2.0–M2.3 核心实现已完成，M2.4 基础比较器与 M2.5 模板样本验证已落地；完整属性覆盖、逐条规则确认和页面视觉验收未完成
> 前置条件：M1 已通过官方模板与真实论文原稿的只读分析
> 输入：官方格式模板、可选批注、模板内容与 OOXML、M1 文档画像及既有 `FormatRule` Schema
> 输出：版本化 SCAU Profile、证据索引、P0 规则、规则装载器与可独立测试的属性验证器

## 1 一句话说明

M2 要把华南农业大学本科论文的格式要求整理成一套有来源、有状态、有版本、可被程序验证的规则，但本阶段不识别整篇论文的语义结构，也不修改 DOCX。

## 2 目标

1. 将官方模板中的明确要求转成结构化 `FormatRule`；
2. 模板没有批注时，仍能从页面、样式、重复内容范例、表格和字段中提取格式观察值；
3. 每条规则保留证据来源和精确定位器，避免凭视觉猜测；
4. 将规则区分为已确定、暂定和待确认，允许系统明确返回“未评估”；
5. 建立首批 P0 属性验证器，为 M3 结构识别和后续只读诊断提供稳定接口；
6. 保持 Rules-only 模式可运行，不依赖模型 API；
7. 不改变 M1 的四类产物及其字段含义。

## 3 非目标

- 不自动判断任意学校的模板；
- 不调用大模型识别标题、正文或图题；
- 不自动修改字体、段落、分页、页眉页脚或目录；
- 不检查论文论述质量、引用真实性和学术规范；
- 不承诺本阶段可以输出“整篇论文格式是否合格”的最终结论；
- 不把真实论文、模板全文、批注全文或分析产物提交到 Git。

## 4 证据与规则状态

### 4.1 证据等级

| 等级 | 证据类型 | 使用方式 |
|---|---|---|
| A | 学校发布的文字版规范、模板内明确批注 | 可以提出确定值，仍需人工确认其适用年份和权威性 |
| B | 模板中重复出现且格式一致的内容范例 | 可提出暂定规则，必须记录样本数、冲突和置信度 |
| C | 官方 DOCX 的 OOXML、样式、分节、字段和表格边框 | 用于提取模板实际值和交叉验证，不自动等同学校规定 |
| D | 页面渲染后的视觉观察 | 用于发现冲突和布局问题，不单独建立规则 |
| E | 个人经验、其他学校规范或模型推断 | 不进入 P0 Profile |

当 A 级证据与模板实际设置冲突时，以学校明确批注或文字规范为准，并把模板实际值记录为偏差样本。模板没有 A 级证据时，使用 B/C 级观察值生成 `provisional` 候选，不能直接标记为 `confirmed`。

### 4.2 状态映射

| 产品状态 | `RuleStatus` | 进入条件 |
|---|---|---|
| 已确定 | `confirmed` | 有 A 级证据，适用范围明确，并经用户人工确认 |
| 暂定 | `provisional` | 有 A/B 级证据，但尚未完成适用年份或冲突确认 |
| 待确认 | `needs_review` | 缺少证据、存在冲突或边界无法确定 |

状态不能由代码自动升级。只有人工审查证据后，规则才能从 `provisional` 变为 `confirmed`。

## 5 当前证据基线

- 官方模板 SHA-256：`bcac55ef57164ac1c18eeb7a5f563be37cf730947e9fb3c1703e660ba20b8322`；
- 模板内共有 50 条 Word 批注，日期集中在 2024 年 5 月至 7 月；
- 批注明确覆盖封面、摘要、关键词、目录、四级标题、正文、表格、图片、公式、脚注、参考文献、附录和致谢；
- OOXML 显示页面为 A4，五个分节的四边页边距均约为 24 mm；
- OOXML 显示前置分节使用大写罗马页码，但正文页码边界仍需结合渲染或 Word 人工复核；
- 四个表格均被识别为三线表。正文表格的上、下边线为 1.5 pt，表头分隔线为 1 pt，无竖线；英文缩略词表的表头分隔线实际为 0.5 pt，与批注要求的 1 pt 冲突；
- 当前捆绑运行时未提供 LibreOffice，因此本轮没有完成页面视觉核验。视觉核验是规则转为 `confirmed` 前的门槛，不影响建立暂定清单。

证据原文保存在本地 `.paperalign/private-test-cases/evidence/`，由 `.gitignore` 排除。仓库只保存脱敏后的规则摘要和证据定位器。

## 6 M2 数据流

```text
官方模板与学校文字规范
  → 提取页面、分节、样式、重复格式簇、表格、字段和可选批注
  → 无批注时仍生成模板格式证据报告
  → 建立证据索引
  → 将复合要求拆成原子 FormatRule
  → 人工确认状态与适用范围
  → 写入版本化 manifest 和 rules JSON
  → Schema 校验与规则装载测试
  → 对已定位样本运行属性验证器
  → 输出 M2 验收报告
```

M2 的验证器只回答“已知语义角色的某个属性是否符合规则”。把普通段落识别成一级标题、正文或图题属于 M3。

## 8 实施阶段

### M2.0 证据冻结（代码已完成，证据确认进行中）

- 记录官方模板哈希、文件来源、发布日期或获取日期；
- 实现不依赖批注的 `inspect-template` 命令；
- 提取分节、样式使用、直接格式簇和表格边框，且不复制模板正文；
- 批注存在时映射为附加定位器，例如 `template_comment:21`；不存在时不得报错；
- Word 表格边框 `w:sz` 按 1/8 pt 换算，并同时保留原始值与换算值；
- 记录 OOXML 交叉验证项，例如分节页边距、页码格式和标题样式；
- 对冲突、缺失和只能视觉确认的项目建立待确认列表。

完成标志：有批注和无批注模板均能稳定生成证据报告，证据索引可以回答每条 P0 规则“从哪里来”。

### M2.1 有效格式解析（代码已完成）

- 按文档默认值、基础样式、派生段落样式、字符样式和直接格式的顺序合并；
- 分别解析中文字体、西文字体、字号、粗斜体、颜色、对齐、缩进、段前段后、行距和分页约束；
- 对每个最终属性保留最后生效来源，例如 `doc_defaults`、`paragraph_style:<id>`、`character_style:<id>` 或 `direct_run`；
- 同一段内有效格式相同的文本 run 聚合为格式组，避免输出正文；
- 不将模板中偶然的直接格式提升为学校规则。

完成标志：给定正文层段落，可以输出可追溯的有效格式快照。当前已完成，并通过合成继承链与华农真实模板验证。

2026-09-20 补充：本地审计工具已交付，13 段的 92 项属性与本机 Word 一致；修复 ASCII/hAnsi 混用并新增未解析标记。该结果是属性抽查，不替代人工页面视觉验收。

### M2.2 规则模型收口（核心契约已实现）

- 沿用 `FormatRule` 领域概念，收紧原自由格式契约为显式版本 2.0；原 1.0 规则需按迁移说明转换，不静默兼容；
- 统一 `scope`、`property_path`、长度单位、字号和行距表达；
- 字号统一存储为 point，并保留中文字号别名；
- 距离统一使用毫米或 point，OOXML twip 只作为解析层数据；
- 定义 `not_evaluated` 与 `evidence_insufficient` 的返回条件。

已完成：核心原子属性的类型、单位、范围、证据优先级、人工确认记录、格式适配及预检状态；错误规则在 Pydantic 与 JSON Schema 均会被拒绝。完整 P0 清单的原子拆分与逐条 Schema 验收归入 M2.3；复合语义/跨页关系不假装已实现。详细契约见 `docs/architecture/rule-contract-v2.md`。

### M2.3 Profile 编码（已实现）

- 建立 `manifest.json`，包含 profile ID、版本、学校、论文类型、证据哈希和规则文件清单；
- 将 P0 清单拆成机器可读规则；
- 每条规则必须填写 `source`、`implementation`、`validator`、`priority` 和 `auto_fixable`；
- 初始规则默认 `auto_fixable=false`，排版策略在 M6 再确认。

完成标志：装载器能够稳定读取 Profile，重复运行输出一致。

2026-09-20：用户确认单模板范围，排除外国语学院及研究生，不扩展学院定制。Profile 1.0.0 包含 248 条原子规则、36 条证据索引和全部 46 项覆盖记录；14 项全部编码、23 项部分编码、9 项延期。全部通过模型及 Schema；4 条已确认、244 条暂定，不等于 248 条全部具备自动验证能力。

### M2.4 属性验证器

已实现：统一预检、数值等于/上下限/容差、文本/布尔比较、行距模式比较及页面/表格观察值适配。未实现：内容计数与片段定位、页码区域语义、跨页布局、目录/续表关系等。不得宣布本阶段全部验收通过。

- 为页面、字体、字号、对齐、缩进、段距、行距、页码、表格边框和分页约束建立纯函数验证器；
- 验证结果必须包含规则 ID、实际值、期望值、证据、定位信息和判定状态；
- 公式、文本框、复杂域和跨页对象无法可靠判断时返回 `not_evaluated`，不得默认为通过。

完成标志：每类属性至少有通过、失败、未评估三个测试分支。

### M2.5 真实样本验证

已完成官方模板哈希绑定样本回归：3 项通过、1 项失败、108 项证据不足，失败项为缩略词表 0.5 pt / 1 pt 冲突。真实论文暂不套用模板固定序号，待 M3 结构识别后接入。报告见 `docs/reports/m23-profile-report.md`。

- 官方模板作为正向样本，但允许记录模板自身与批注不一致的情况；
- 论文原稿作为问题发现样本，不提交其正文和派生产物；
- 从真实边缘情况中制作最小化合成 fixture；
- 形成 M2 实施报告和面试讲解材料。

完成标志：P0 规则可以被装载，已定位样本可以被验证，所有不确定项都有明确状态。

## 9 验证结果约定

| 结果 | 含义 |
|---|---|
| `pass` | 实际值与规则一致 |
| `fail` | 实际值与规则明确不一致 |
| `not_evaluated` | 当前解析器或验证器不支持 |
| `evidence_insufficient` | 规则本身尚未确认，不能做合规结论 |

暂定规则即使属性匹配，也只能表述为“与当前模板证据一致”，不能表述为“符合学校最终规范”。

## 10 测试计划

1. 每个规则 JSON 通过 Pydantic 和导出的 JSON Schema；
2. Profile ID、规则 ID 和证据定位器唯一；
3. 规则装载顺序稳定，重复运行结果字节级一致；
4. 样式继承、直接格式覆盖、中西文字体和混合字号有单元测试；
5. A4、页边距、标题、正文、图题、表题和参考文献至少各有一组正反 fixture；
6. 不支持对象返回 `not_evaluated`，不产生伪阳性；
7. 对真实文件只输出定位、格式属性和哈希，不输出完整正文；
8. Ruff、mypy、pytest、Schema 导出和既有 M1 回归全部通过。
9. 无批注合成模板能够输出格式证据和正确的三线表磅值；
