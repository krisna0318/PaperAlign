# M6 执行方案：确定性安全排版

日期：2026-09-21。状态：已完成首个受控适配器。

## 一句总结

只有“规则已人工确认、结构已无歧义、适配器已实现、用户本次明确批准”四个条件同时成立，系统才生成新的 DOCX 副本。

## 首批范围

当前 248 条原子规则中只有英文缩略词表三线表的 4 条边框规则已确认。因此 M6 首批适配器只处理：顶线 1.5 pt、表头分隔线 1 pt、底线 1.5 pt、无竖线。其余 244 条规则继续保持只读诊断。

## 安全闸门

1. 四条规则必须整组批准，部分批准拒绝执行。
2. 目标必须被 M3 确认为 `abbreviation_table`，且不需要人工确认。
3. 宏、嵌入包、altChunk 等阻断对象存在时拒绝排版。
4. 输出路径不得等于输入路径，也不得覆盖已有文件。
5. 只重写 `word/document.xml` 的目标表格边框；其他包部件原样复制。
6. 输出完成后重新做 M1 分析，内容指纹不同则删除临时输出并失败。
7. 每条规则记录目标、定位、修改前后表格 XML 指纹；最终页面仍交给 M7。

## 模块接口

- 核心：`build_formatting_plan` 与 `format_docx`，不依赖 Web。
- CLI：`format-copy`，要求显式确认参数并输出 plan/report。
- API：`POST /api/jobs/{id}/format`；结果可由 `GET /api/jobs/{id}/download` 下载。
- UI：仅在检测到合格目标时显示规则确认卡和生成按钮。

## 后续扩展方式

新增规则不能修改现有适配器的隐式行为。每组格式必须先确认 Profile，再新增独立适配器、前后观察器和合成回归样本；页面布局、目录域和分页不能伪装成静态 OOXML 已验证。
