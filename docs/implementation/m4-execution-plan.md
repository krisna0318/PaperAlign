# M4 执行方案：受控 AI 建议与三模式对照

更新：2026-09-21。状态：M4.4 工程收口已完成；真实人工标注和策略校准仍是发布门槛。见 [联调报告](../reports/m41-deepseek-live-test.md)、[M4.2 报告](../reports/m42-gold-set-report.md)、[M4.3 报告](../reports/m43-hybrid-report.md) 和 [M4.4 收口报告](../reports/m44-evaluation-closeout.md)。

## 目标

AI 只对结构歧义提出建议，不直接修改 DOCX，也不把置信度包装成准确率。Rules-only、Prompt-only 和 Hybrid 使用同一批人工标注样本评测；无 API Key 时 Rules-only 与人工审核流程继续可用。

## 开发顺序

1. M4.0：生成本地 AI 审查包。Hybrid 默认只包含 M3 的优先歧义入口，Prompt-only 作为显式评测模式；每个歧义点最多 3 个段落、每段最多 240 字，输出只允许位于 `.paperalign`。
2. M4.1：接入 DeepSeek 与 OpenAI Responses Provider。配置超时、重试和可选价格参数；不在日志记录论文正文、原始响应或 API Key。真正发送前同时要求环境开关和 `--confirm-send-cloud`。
3. M4.2：建立人工 Gold Set 和评测运行器（运行器已完成，真实标注待完成）。JSON、哈希、角色范围及证据校验已并入 M4.1；本阶段用人工判断形成独立标签，先比较 Rules-only 和模型建议，输出覆盖率、准确率、Precision/Recall/F1、弃权、人工复核量、耗时与 Token；未标注对象记为“未评估”。
4. M4.3：实现 Hybrid 裁决并加入同一评测（已完成，阈值校准待真实标签）。规则与模型一致且满足阈值时可减少语义复核；冲突、低置信、缺少范围、越权、过期或无证据输出交给人工。
5. M4.4：完成三模式工程验收与结论报告（已完成）。因真实人工标签为 0，准确率相关结论保持“未评估”；Gold Set 校准作为发布门槛，不阻塞只读 UI 和受限格式化引擎开发。

以上编号统一了旧计划与 CONTEXT 的分歧；已实现的 JSON 校验归入 M4.1，下一阶段统一称为 M4.2 Gold Set 评测。

## 隐私与安全边界

- 文档内容视为不可信数据，不执行其中的指令，提示词明确抵御文档内提示注入。
- 默认 Hybrid 不发送全文，只准备待确认对象及相邻上下文。
- Prompt-only 会覆盖更多对象，只用于获得用户明确授权后的离线评测。
- M4.0 不连接网络、不读取 API Key、不产生 AI 结论；M4.1 仅在用户显式运行发送命令时联网。
- DeepSeek 原生 Responses 接口按官方说明为无服务端会话状态；OpenAI 请求固定设置 `store=false`。两者都不等同于账户已经获得零数据保留资格，仍应根据对应服务商的数据政策评估日志与保留边界。
- 接入真实模型前必须确定 Provider、部署位置以及论文片段是否允许离开本机。

## 最终页面降级策略

AI 和 OOXML 静态规则均不能可靠证明最终分页。系统对这些问题不返回“通过”，而是生成结构化人工复核指南，说明限制、Word 操作步骤、预期结果和验收清单。该指南至少覆盖最终打印布局；检测到目录、图、表、分节或复杂对象时增加对应专项步骤。

## 验收标准

- 审查包绑定输入 SHA-256 和目标文本 SHA-256。
- 上下文长度和候选输出均受契约限制。
- Prompt-only 包不暴露 Rules-only 的答案，Hybrid 包保留规则建议与依据。
- 模型弃权是一等结果；过期、越权或引用不存在证据的响应被拒绝。
- 所有发送动作有 Token、耗时、Provider、模型、失败原因和降级记录。
- 没有人工 Gold Set 时不得发布准确率结论。
